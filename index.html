// 00 — por qué “oblique”

Una línea que no sigue los ejes obvios

Los problemas complejos rara vez se resuelven de frente. Nuestro trabajo es encontrar el ángulo que los vuelve simples.

principios.md
01
Entender antes de construir
Cada proyecto empieza con preguntas: cuál es el problema, para quién, y qué pasa si no se resuelve. El código llega cuando la respuesta es clara.
02
La experiencia es funcionalidad
Un sistema se mide por cómo se usa. Diseñamos interfaz y arquitectura como una sola pieza, porque para el usuario lo son.
03
Software que dura
Decisiones documentadas y código que tu equipo puede mantener y extender sin nosotros. Ese es el estándar desde el primer commit.

// 03 — el método oblique

No es un problema si lo ves desde el ángulo correcto

Cada paso inclina la perspectiva un poco más. Al llegar a 45°, aparece la línea oblicua: el camino directo entre el problema y la solución.

paso 01
θ = 0° → 11°
Discover
Entendemos el problema real, no el síntoma.
paso 02
θ = 11° → 22°
Design
UX y arquitectura se diseñan juntas, y se validan con usuarios.
paso 03
θ = 22° → 34°
Build
Ciclos cortos, entregas frecuentes, decisiones documentadas.
paso 04
θ = 34° → 45°
Ship & Iterate
Lanzar es el inicio: medimos y ajustamos con uso real.
paso 05
θ = 45° = oblique
Handoff
Tu equipo queda autónomo, con el conocimiento y el código para seguir solo.
